MerchantDetection

class MerchantDetection : Parcelable

Signals describing how the recognizer arrived at a merchant for this scan — which detectors fired, what each of them matched, and how confident it was. These are diagnostics, not results: the merchant the scan settled on is ScanResults.merchantName. They are forwarded to the Activation backend so a mis-detected merchant can be traced back to the detector responsible for it.

Only the detectors that actually ran populate a value; everything else stays null.

phoneMatch2/phoneBanner2 mirror the wire contract for parity with iOS and the Activation SDK, but nothing on Android currently populates them.

The backing fields carry @SerializedName with the merchant_detection[...] keys the Paper API receives (see MerchantDetectionResultsMapper), so a Gson dump of a scan can be diffed directly against the merchant_detection_sources table. Without them Gson would reflect over the raw field names and emit _phoneMatch, which matches neither the accessors nor the wire format — and consumer-rules.pro keeps only public fields by name, so the annotation is also what keeps these keys stable in minified builds (-keepattributes *Annotation*).
